Root cause A — Site-row DOM walking is brittle (3 tests) NEEDS FED DATA-HOOK
View Failing Tests & Fix
Failing tests:
  • §2 P0 — Select free site → site-level split page (URL changes)
  • §3 P0 — Select Free site → site-level upgrade (URL changes)
  • §3 P0 — Select Premium site → site-level Connect (URL changes)
Symptom: expected to click a [free|premium] site label · Expected: true Received: false — the selectSiteByType helper returns false because it can't find a row matching the type.
Two helper rewrites tried: (1) label.filter({ has: input[type="radio"] }) — labels don't wrap the radios. (2) DOM walk up looking for an ancestor with 5-200 chars text — picks the wrong-grain ancestor.
Suggested fix: Get an actual data-hook from the FED team for the site-selector row (e.g. data-hook="site-selector-row" with sub-hook premium-badge). Five-minute fix once we have it.
Root cause B — Multi-step gate flow flake (4 tests) TIMING / RETRY-NOT-ENOUGH
View Failing Tests & Fix
Failing tests:
  • §3 P0 — Clicking Connect on taken domain opens upgrade modal or site selector
  • §3 P1 — Has-sites: "Continue without a site" side action visible
  • (§1 / §2 various tests have flaked across runs but eventually pass)
Symptom: Helper chain (login → my-domains → Buy a Domain → gate → search → wait for AI suggestions → click Connect → wait for modal) has ~20-40% cumulative flake rate. Even with retries: 1, both attempts can fail.
Suggested fix: Split openConnectSiteSelector into smaller, more-deterministic steps with longer per-step timeouts; or increase global retries to 2; or wait for a specific data-hook (e.g. data-hook="ai-suggestions-loaded") instead of generic networkidle.
§2 P0 — Select free site → site-level split page (URL changes) SELECTOR MISS
View Root Cause & Fix
Symptom: Error: expected a non-premium site card to be clickable
Where: account-level-gate.spec.ts:248
Root Cause: My heuristic iterates clickable elements in the modal looking for one whose textContent does NOT contain "Premium". With 2 sites in this account (1 premium, 1 free), the iteration didn't find a free-site card — possibly because the free site card text also contained "Premium" somewhere (e.g. "Upgrade to Premium" CTA inside the row).
Suggested Fix: Open the modal in a diag run, dump the actual data-hooks on each site card (likely site-card, site-row, site-item) plus the badge/CTA inside, then target the free site by its specific data-hook (probably data-hook="site-row" that does NOT contain a child with data-hook="premium-badge").
§2 P1 — "Continue without a site" side action visible FLAKE — MODAL DIDN'T OPEN
